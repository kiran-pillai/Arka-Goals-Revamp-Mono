Why the entry shape decides this

A checkbox needs a stable identity to toggle — an id to write completed against. A line inside a text blob has no identity: it shifts when the user edits the paragraph, and re-parsing on every read would silently reassign completions to the wrong item.

Capturing discrete items at entry is the only way the toggle state stays attached to the thing the user actually committed to.

Contract change — both sides ship together. commitments goes from string to string[] on the POST body. Because the API runs ValidationPipe with whitelist: true and forbidNonWhitelisted: true, the old shape is rejected with a 400 rather than silently coerced — so a frontend deployed without the matching DTO would break every submit.

One open choice, and my recommendation. Should the weekly form pre-fill last week’s commitments so a user can carry them forward with one click? It’s a real convenience for recurring items like “No dating apps,” but it also nudges people to re-commit by default instead of deciding fresh each week. I’d leave it out of v1 — easy to add later once you can see from the data how often items actually repeat.
