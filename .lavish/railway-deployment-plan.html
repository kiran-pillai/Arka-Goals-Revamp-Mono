Implementation Steps

1
Create production Docker Compose
New file
▾

Add docker-compose.prod.yml at the repo root to wire all three services together for both local testing and Railway.

# docker-compose.prod.yml services: db: image: postgres:16-alpine environment: POSTGRES_DB: arka ... volumes: - pgdata:/var/lib/postgresql/data api: build: ./back-end depends_on: [db] environment: DATABASE_URL: postgresql://... ... ports: ["3000:3000"] frontend: build: ./front-end depends_on: [api] environment: API_UPSTREAM: http://api:3000 ports: ["80:80"]
2
Make nginx upstream configurable
Modify
▾

The current nginx.conf hardcodes http://api:3000/. We'll template it so Railway's internal service URL is injected at container start.

FileChange
front-end/nginx.conf Replace http://api:3000 with ${API_UPSTREAM} placeholder
front-end/Dockerfile Add envsubst entrypoint to resolve the template at startup
# nginx.conf.template (the key change) location /api/ { proxy_pass ${API_UPSTREAM}/; ... } # Dockerfile addition CMD ["sh", "-c", "envsubst '${API_UPSTREAM}' < /etc/nginx/conf.d/default.conf.template > /etc/nginx/conf.d/default.conf && nginx -g 'daemon off;'"]

4
Deploy to Railway
Manual
▾

One-time setup on Railway's dashboard or CLI.

  • Push repo to GitHub (if not already)
  • Create a new Railway project
  • Add PostgreSQL plugin (one click — DATABASE_URL auto-injected)
  • Add "api" service → point to back-end/ directory
  • Add "frontend" service → point to front-end/ directory
  • Set environment variables on each service
  • Configure custom domain (optional)
  • Deploy — Railway builds Dockerfiles and starts services

▾

End-to-end verification checklist.

  • Test locally: docker compose -f docker-compose.prod.yml up --build
  • Frontend loads at the public URL
  • API proxying works: /api/ routes reach NestJS
  • Database migrations ran (check Railway deploy logs)
  • Magic-link login flow sends email via real SMTP
  • Create a goal and verify it persists

SMTP Setup Guide

📧
Resend Recommended
Free tier: 3,000 emails/month, 100/day — plenty for magic-link auth
Setup Steps
  • Sign up at resend.com (GitHub OAuth, takes 30 seconds)
  • Go to Settings → API Keys → create a key (save it — shown once)
  • Go to Domains → add your domain (e.g. arka.yourdomain.com)
  • Add the DNS records Resend gives you (SPF, DKIM, DMARC) — 3 TXT + 1 MX record
  • Wait for verification (usually 1–5 minutes)
  • While waiting, you can test with onboarding@resend.dev as the sender
Railway Environment Variables
SMTP_HOST=smtp.resend.com SMTP_PORT=587 MAIL_FROM=Cheetah Squad <noreply@yourdomain.com>
⚠️ Code Change Required
The current mail.service.ts uses secure: false and no auth — fine for MailHog in dev, but production needs SMTP auth. You'll need to add:
// mail.service.ts — production transport config this.transporter = nodemailer.createTransport({ host: app.smtpHost, port: app.smtpPort, secure: app.smtpPort === 465, auth: app.isProd ? { user: 'resend', pass: app.smtpApiKey, // SMTP_API_KEY env var (your Resend API key) } : undefined, });
New Env Var Needed
SMTP_API_KEY
Your Resend API key — used as the SMTP password. Resend uses resend as the username.
Get from: resend.com → Settings → API Keys
