First, what the data can support today

Worth knowing before picking a layout: most of these metrics have no backing data yet. Only check-in submission and team accountability are derivable from the current schema. That doesn't change the design, but it does change how much of it can be real in v1.

Decisions that unblock implementation

Pick per question and hit Queue — each sends one answer back to me.

1. Which layout direction?

Drives the whole component structure.

2. How to handle the metrics with no data?

Six of ten sections need new schema. This decides what v1 actually ships.

3. Where does the "My Dashboard" button go?

You asked for a separate button from the existing two.

4. What defines a "week"?

Submission rate, streaks, and "next deadline" all depend on this. Nothing in the schema encodes it today.
